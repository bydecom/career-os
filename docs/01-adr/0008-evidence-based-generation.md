# ADR-0008: Evidence-based Generation

**Status:** Accepted  
**Date:** 2026-07-13  
**Owner:** Bang Thai Minh

---

# Context

When an AI answers a recruiter's question (e.g., "Tell me about your experience scaling microservices"), a generated paragraph of text is not enough. In a technical interview context, claims must be backed by proof. Traditional chatbot portfolios fail because they "tell" rather than "show".

---

# Requirements

- Every technical claim generated by the system must point to a specific, verifiable artifact.
- The frontend must be able to parse AI responses and render rich UI widgets (not just text links) for the evidence.

---

# Considered Options

## Option A — Plain Text Citations
### Advantages
- Easy to prompt the LLM to do (e.g., "Append [1] at the end").
### Disadvantages
- Poor UX. Clicking a footnote to read a link is not an engaging "Show, don't tell" experience.

Decision:
❌ Rejected

## Option B — Evidence-based Generation via XML/Markdown Tags
### Advantages
- The LLM embeds structured tags (e.g., `<evidence type="diagram" src="..." />`) directly into the markdown stream.
- The UI intercepts these tags and renders interactive React components inline.
### Disadvantages
- Requires strict prompt engineering to force the LLM to use the exact schema.

Decision:
✅ Accepted

---

# Decision

CareerOS implements **Evidence-based Generation**. 

Every answer must trace back to an `Evidence` or `Decision` node in the Knowledge Graph. The LLM is instructed via the System Prompt to output custom UI tags whenever it mentions an achievement or architecture decision. The React frontend will parse these tags and render rich widgets (e.g., an Architecture Viewer, a GitHub Commit Card, or a Benchmark Table) directly inside the chat flow.

---

# Consequences

## Positive
- Creates a "Wow" factor for recruiters (Live Evidence).
- Forces the LLM to remain grounded to actual nodes.

## Negative
- The UI layer becomes more complex (requires a custom Markdown/Stream parser).

---

# Design Principles

## Evidence First
Every answer must be traceable back to real nodes (Code, Commit, Architecture Diagram, Benchmark).
