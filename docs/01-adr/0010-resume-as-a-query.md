# ADR-0010: Resume as a Query

**Status:** Accepted  
**Date:** 2026-07-13  
**Owner:** Bang Thai Minh

---

# Context

Candidates typically maintain multiple PDF resumes for different roles (e.g., Backend Developer, Fullstack Developer, AI Engineer). This leads to fragmentation and desynchronization of career details. When a skill is updated, it must be manually edited across all PDF/Word templates.

---

# Requirements

- A resume should not be a static document.
- The system must generate a customized resume dynamically based on a target Job Description (JD).
- Information must remain consistent across all generated resumes.

---

# Considered Options

## Option A — Multiple Static Markdown/PDF Resumes
### Advantages
- Easy to manage individually.
### Disadvantages
- Painful to sync updates across files.
- Static and not tailored to specific JDs.

Decision:
❌ Rejected

## Option B — Resume as a Graph Query
### Advantages
- The candidate uploads a Job Description. The system runs a query (e.g., using semantic match or key entity matching) on the Career Graph to retrieve the top N nodes (projects, skills, decisions) matching the JD requirements.
- Compiles the retrieved nodes into a perfectly tailored PDF Resume.
- Ensures all updates are centralized (Single Source of Truth).
### Disadvantages
- Requires building a robust layout compiler (Markdown/HTML -> PDF).

Decision:
✅ Accepted

---

# Decision

A Resume is defined as a programmatic Query over the Career Knowledge Graph. The PDF is generated by compiling the query results (nodes and edges) into a standard layout dynamically.

---

# Design Principles

This decision directly implements the following core principles:
- **Composable Knowledge**: Tri thức có thể lắp ghép linh hoạt.
- **Single Source of Truth**: Sửa thông tin ở một Node sẽ cập nhật tất cả các CV được sinh ra sau này.
